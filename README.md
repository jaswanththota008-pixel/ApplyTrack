# ApplyTrack — Job & Internship Application Tracker

Track job and internship applications from **Saved → Applied → Assessment → Interview → Offer / Rejected**, with a dashboard, list + Kanban views, deadline and interview reminders, a notification center, browser notifications, and per-user privacy.

## Tech stack
- React 19 + TypeScript, TanStack Start/Router (file-based routes in `src/routes`)
- Tailwind CSS v4 (design tokens in `src/styles.css`, light + dark themes), shadcn/ui components
- Lovable Cloud (Postgres + Auth, Supabase-compatible) via `@supabase/supabase-js`
- TanStack Query for data fetching, react-hook-form + zod for validation, Recharts, dnd-kit

## Features
- **Auth**: email/password sign-up (email confirmation), login, logout, password change, protected routes, session persistence.
- **Applications**: full CRUD with validation; types Full-time / Internship / Part-time / Contract / Other; statuses Saved → Rejected; priorities Low/Medium/High; company website, posting URL, notes, applied date, deadline, interview date/time.
- **Views**: list + drag-and-drop Kanban board, search, filters (status/type/priority), sorting (updated, deadline, applied, priority, company).
- **Dashboard**: totals, active, interviews, offers, rejected; status distribution pie; applications-per-week chart; upcoming deadlines/interviews; recently updated. All computed from real records.
- **Notification center**: bell with unread count, mark read / mark all read / dismiss, links to applications. Persistent, per-user, deduped by event key.
- **Reminders**: deadline (3 days / 1 day / today / optional overdue) and interview (within 24 h) reminders, generated both in the browser on login and by an hourly scheduled database job (`generate_reminders()` via pg_cron, idempotent by event key).
- **Browser notifications**: opt-in from Settings, permission-aware, shown while the app is open. (True background Web Push is not enabled — see "Known limits".)
- **Preferences**: email/browser toggles, per-reminder-type toggles, timezone — stored per user in the database.
- **Themes**: light / dark / system, saved locally.

## Database schema
**profiles** — `id` (= auth user id, PK, FK auth.users ON DELETE CASCADE), `full_name`, `university`, `target_role`, timestamps. Auto-created by a trigger on sign-up.

**applications** — `id`, `user_id` (defaults to `auth.uid()`), `company`*, `role`*, `type` (job|internship|part_time|contract|other), `status` (saved|applied|assessment|interview|offer|rejected), `priority` (low|medium|high), `company_website`, `posting_url`, `notes`, `applied_date`, `deadline`, `interview_at`, `created_at`, `updated_at` (trigger-maintained). Indexed on `deadline` and `interview_at`.

**notification_preferences** — one row per user: `email_enabled`, `browser_enabled`, `deadline_reminders`, `interview_reminders`, `overdue_reminders`, `timezone`. Auto-created on sign-up.

**notifications** — persistent in-app events: `event_key` (unique per user, prevents duplicates), `kind`, `title`, `body`, `application_id` (cascade-deletes with the application), `read_at`, `dismissed_at`.

**push_subscriptions** — browser push endpoints per user (reserved for future background Web Push).

**email_events** — email reminder delivery log: unique `event_key`, `recipient`, `subject`, `status` (pending/sent/failed/suppressed/skipped). Users can read their own rows; only the backend writes.

Server-side validation: CHECK constraints for lengths and `http(s)://` URLs, enums for status/type/priority. Client-side the same rules are mirrored in zod.

### Security (Row Level Security)
RLS is enabled on every table. Every policy is `auth.uid() = user_id` (or `= id` for profiles), so a user can only select/insert/update/delete their own rows — enforced by the database even if someone calls the API directly. The anon role has no grants. `email_events` is read-only for users; `generate_reminders()` is executable only by the service role. Only the public publishable key is used in the browser; no service-role key is in client code.

### Scheduled jobs
- `applytrack-generate-reminders` — pg_cron, hourly at minute 17, runs `SELECT public.generate_reminders()`. Idempotent: event keys prevent duplicate notifications/emails across runs.

## Local setup
1. `bun install` (or `npm install`)
2. Create `.env` with the `VITE_SUPABASE_*` values above (from your own Supabase project if self-hosting).
3. Apply `drizzle/migrations/*.sql` to that database (SQL editor or `psql`).
4. `bun run dev` → http://localhost:8080
5. Tests: `bun run test` (vitest — reminder logic, routing).

## Deployment
Publish from the Lovable editor (Publish button). Database changes apply immediately; frontend changes go live when you click Update in the publish dialog.

## Known limits / manual steps
- **Email reminders**: the reminder pipeline and delivery log are built, but sending requires a sender domain you own (set up via the Lovable email setup). Until then, reminders appear in the notification center only.
- **Background Web Push**: not enabled — browser notifications are shown while ApplyTrack is open. True background push would need VAPID keys and a push service worker.
- **Sign-up** requires email confirmation; use real email addresses when testing multiple accounts.
- No demo data is seeded; every account starts with an empty, private workspace.
